The intended forward-compatible behavior — unknown fields silently ignored — is serde's *default* when `deny_unknown_fields` is simply never applied, which is the case here. Implemented via `rmp_serde::from_slice` paired with `to_vec_named` on the encode side (named-map encoding, not positional-array), since positional encoding would make "extra/reordered fields" ill-defined for forward compatibility in the first place
