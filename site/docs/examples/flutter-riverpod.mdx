# Tutorial: Flutter + Riverpod + A2UI

`examples/flutter-riverpod` proves the mobile slice of the 3.0 contract: a
Flutter/Riverpod 3 app renders official A2UI surfaces and drives optimistic
CRUD plus offline persistence/convergence against the certified
`entity_graph_flutter@3.1.0` package.

## Architecture

The app composes published surfaces only — no library changes:

- `entity_graph_flutter` — the canonical Dart graph plus Riverpod provider
  families (`entityListProvider`, `entityCrudProvider`, …).
- `a2ui_flutter@0.3.0` with the `a2ui_core@0.7.0` message processor — the
  official renderer, consuming A2UI 1.0 (`version: "1.0"`) natively with no
  translation layer. The showcase uses its own narrowed catalog
  (`urn:prometheus-ags:a2ui:catalog:flutter-showcase-1.0`: Card, Column, Row,
  Text, Button, Divider; no client functions).
- An **app-owned, fail-closed action policy**: agent output is limited to
  `createSurface`, `updateComponents`, `updateDataModel` and `deleteSurface`
  for the registered surface, the main screen may only name the declared
  actions `task.update`, `task.archive` and `task.delete`, and a refused batch
  renders a refusal card without writing to the graph. Every user action still
  passes the Riverpod action policy before any graph mutation.

Mutations land once in the normalized graph and propagate to every joined
view — the same invariant the TypeScript bindings certify.

## Setup

```bash
pnpm run dart:bootstrap          # flutter pub get across the pub workspace
cd examples/flutter-riverpod
flutter run                      # attach a device or emulator
```

## Feature scenarios

| Scenario | Coverage ID | What to watch |
| -------- | ----------- | ------------- |
| A2UI render + policy | `example.protocol.a2a-a2ui-policy` | Surface actions cross the app-owned policy |
| Optimistic CRUD | `example.crud.optimistic-confirm`, `example.crud.optimistic-rollback` | Edit buffer isolation, save/rollback semantics |
| Offline persistence + convergence | `example.offline.persistence-convergence` | Persisted graph reloads; offline edits converge |
| Cross-view normalization | `example.graph.normalized-cross-view` | One canonical entity drives every widget |
| Platform boundary | `example.platform.adapter-boundary` | Mobile host stays a transport adapter |
| Schema round-trip | `example.schema.roundtrip` | Dart models match the shared SDL schema |

## Deployment and platform notes

Android and iOS scaffolding live in the example (`android/`, `ios/`). Build
receipts: debug APK and an unsigned iOS simulator bundle. Release signing,
store upload, and device certification remain downstream operator work.

## Troubleshooting

- **Provider family forking per rebuild:** lambda `toGraph` closures recreate
  Riverpod families; use static `encode` tear-offs instead.
- **CRUD provider dies between read and save:** watch `.notifier` from the
  tile so the auto-dispose provider stays alive.
- **Conflict merge loses the base value:** fixed in the example's merge path;
  keep merge strategies total when forking.
