# DevTools & Graph Pulse

:::info Current versions

React DevTools ships in npm `3.2.0` through `./devtools` and
`./devtools/auto`. Flutter `3.1.0` is published on pub.dev with the controller
and official Flutter DevTools companion documented below.

:::

The optional React DevTools answer 3 questions from one store-scoped causal
workspace:

1. What changed?
2. What is dirty and still uncommitted?
3. Which registered rendered views are affected?

The normal `@prometheus-ags/prometheus-entity-management` entry does not import
or mount this UI. Applications opt in through an optional development entry.

## Vite: Automatic Development Launcher

Add one guarded dynamic import to the client entry:

```ts
if (import.meta.env.DEV) {
  void import("@prometheus-ags/prometheus-entity-management/devtools/auto");
}
```

Vite replaces the condition at build time. The auto entry then checks the
browser and host mode before it mutates the document or requests the lazy
inspector chunk. Production and disabled modes render nothing.

## Next.js: Explicit Post-Hydration Host

Server markup must remain unchanged. Mount the explicit host from a client
component after hydration and give it the same request/provider-owned graph as
the application:

```tsx
"use client";

import { useEffect, useState } from "react";
import type { GraphStore } from "@prometheus-ags/entity-graph-core";

type Host = typeof import(
  "@prometheus-ags/prometheus-entity-management/devtools"
)["EntityGraphDevtools"];

export function DevelopmentGraphTools({ store }: { store: GraphStore }) {
  const [Host, setHost] = useState<Host | null>(null);

  useEffect(() => {
    if (process.env.NODE_ENV === "production") return;
    let active = true;
    void import("@prometheus-ags/prometheus-entity-management/devtools")
      .then((module) => {
        if (active) setHost(() => module.EntityGraphDevtools);
      });
    return () => {
      active = false;
    };
  }, []);

  return Host ? <Host mode="auto" store={store} /> : null;
}
```

## Launcher Controls

After opt-in, development mode displays a floating **Graph** launcher. Its
display menu can:

- move the launcher to any corner;
- switch it to a compact edge tab;
- dock the inspector right or bottom, or keep it floating;
- hide it until reload; or
- hide it for the current browser preference.

Press <kbd>Ctrl</kbd>/<kbd>Cmd</kbd>+<kbd>Shift</kbd>+<kbd>G</kbd> to open,
restore, or close the inspector. The shortcut and preference key are
configurable through the explicit host API. Focus returns to the launcher when
the panel closes.

## Causal Workspaces

| Workspace | What it proves |
| --------- | -------------- |
| **Overview** | Store health, dirty/error/fetching counts, registered vs. rendered views, event rate, and bounded event/snapshot retention. |
| **Entities** | Search/filter, original/patch/live/diff values, dirty reasons, relationships, rendered-view membership, preview/restore, and per-entity history. |
| **Views** | Truthful registered membership, subscriber/render counts, list completeness/freshness, and the last event that changed the view. |
| **Activity** | Ordered retained publications, correlation IDs, affected entities/views, time-travel snapshots, rewind, and return to live. |

**Graph Pulse** remains visible across the workspaces. Selecting a pulse
segment follows one real publication to its entities, dirty fields, and every
registered view attributed by the controller. It does not infer rendered
visibility from list membership alone.

## Original, Patch, Live & Diff

- **Original** is the server-confirmed canonical entity.
- **Patch** is the local graph overlay that has not yet been committed.
- **Live** is the merged value application hooks currently read.
- **Diff** identifies added, changed, and removed field paths without relying
  on color alone.

Preview applies a local patch through the real graph action and returns a
revision-bound receipt. Restore reinstates the exact prior patch only if the
entity revision still matches; a conflict leaves the newer graph state intact.
This is separate from time travel, which rewinds the controller-owned complete
graph snapshot and always exposes **Return to Live**.

## Value & Security Boundary

The embedded same-origin inspector can read its selected local store. Values
that cross a serialized browser, VM-service, or remote transport remain
metadata-only by default. A host must explicitly choose include mode and apply
its redactor before values may enter that transport. Hidden, redacted,
truncated, unavailable, and actual `null` states remain distinguishable.

This boundary exists because entity values can contain credentials, personal
data, or tenant-scoped business records. The inspector never grants commit or
server-mutation authority to a transport.

## Core Controller APIs

The React inspector consumes the optional
`@prometheus-ags/entity-graph-core/devtools` controller rather than creating a
second graph or history store. Advanced hosts can attach controllers, register
custom rendered views, consume versioned projections/events, preview patches,
and drive stable-cursor time travel directly.

The older root-level `createDevtoolsEventBus`, store registry, and snapshot
helpers remain available for compatibility, but new inspection UIs should use
the store-scoped controller contract.

## Chrome DevTools panel

The private Manifest V3 workspace in `extension/` packages this same inspector
as an **Entity Graph** panel. Build it with
`pnpm --filter @prometheus-ags/entity-graph-chrome-devtools package`, load
`extension/dist` as an unpacked extension, and open DevTools on an application
that renders `<EntityGraphDevtools />`.

The panel reconnects across navigation and worker restart, routes each inspected
tab independently, and retains the host controller's metadata/redaction policy.
Its declarative content script runs on HTTP(S) pages; the page-visible bridge is
not an authentication boundary and should remain a development-only opt-in.

## Flutter DevTools companion

Flutter `3.1.0` includes `extension/devtools/config.yaml` plus the compiled
official package extension. Attach an `EntityGraphDevtoolsController` from
`package:entity_graph_flutter/devtools.dart` in a debug app. The packaged
workflow is designed for Dart DevTools to discover overview, entities,
views/relationships, and activity workspaces with explicit loading,
disconnected, incompatible, error, and ready states.

The VM-service methods are absent in product mode, store selection is explicit,
and values stay metadata-only unless the app supplies an include/redaction
policy. The extension cannot weaken that policy. Publication, static extension
validation, and a clean consumer release build pass; an end-to-end connected
DevTools-host certification is not claimed.

## Evidence Boundary

The packed React gate exercises clean Vite and Next consumers plus Chromium
workflows for production exclusion, automatic activation, hide/restore,
dirty/original/view/history causality, hydration, keyboard and screen-reader
accessibility, responsive layouts, and a sustained 500-event interaction.

```bash
pnpm run verify:devtools-react-inspector
```

The retained phase receipt records the exact machine and timings. The unstarted
12-developer formative study is retained as optional post-release research and
is not represented as passed. No “world class” usability-certification claim is
made from automated evidence.
